# AZ-305 visual direction

Purposeful editorial architecture illustrations, not generic boxes linked by arrows. Distinct from basic AZ-900 overview material: explain consequential design choices and failure boundaries.

## Visual system

Deep navy, cyan, off-white and restrained amber. Architectural cutaways, regional landscapes, layered trust boundaries, data textures and service silhouettes. Use genuine Azure service icons only from the official package under its terms, unmodified and clearly labeled. Original illustrations are not official diagrams.

## Suggested meaningful plates

1. **Identity lens:** distinct human and workload access paths, permission scope shown as nested transparent boundaries. Caption distinguishes authentication from authorization.
2. **Data landscape:** transactional ledger, document collection and object archive on separate but related terrain. Caption explains access patterns rather than implying all data flows everywhere.
3. **Recovery landscape:** two regional environments with separate failure boundaries and an explicit recovery timeline. Label RPO and RTO correctly; do not use decorative uptime claims.
4. **Compute spectrum:** platform responsibility as a continuum from operating-system control to managed execution. Preserve the point that managed services still require application ownership.
5. **Network geography:** public edge, application zone and private data zone with service icons and restrained labeled traffic paths. Include DNS and identity dependencies in text.
6. **Migration transition:** current and target environments with a deliberately visible interim state and cutover boundary, not a magic instantaneous arrow.

Every illustration needs accessible alternative text and a short 'what this shows / what it does not prove' caption. No invented portal screenshots. Source screenshots should be captured from the actual official public page, attributed and dated.
